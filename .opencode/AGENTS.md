# AGENTS.md

## Repo Shape

- Project is using jj-vcs (not git).
- This is a single Go module, `github.com/rupor-github/gencfg`, containing both the importable `gencfg` package at the repo root and the CLI in `cmd/tool`.
- Public library entrypoints are `Process` in `generate.go`, template values/functions in `template.go`, `Sanitize` in `sanitize.go`, and `Validate` in `validator.go`.
- `misc/version.go` is generated by Taskfile build tasks; do not hand-edit it unless the task is specifically about generated build metadata.

## Toolchain

- `go.mod` and `Taskfile.yml` require Go `1.26.0` or newer.
- Taskfile pins `GOTOOLCHAIN=local+path` and sets `GOPATH` to `/tmp/gopkg_gencfg_<go-version>` by default; prefer `task` commands when available so these env settings and generated files are handled consistently.
- The build uses Go tool dependencies from `go.mod`: `go tool autotag` for version generation and `go tool staticcheck` for linting.

## Commands

- `task` or `task debug`: generate `misc/version.go`, build debug CLI to `build/gencfg`, compile all tests, and run staticcheck.
- `task release`: generate version metadata and build release CLI to `build/gencfg`.
- `task test`: run all packages with `*_test.go` using `go test -race -v`; coverage files go under `build/tests_results`.
- `PACKAGES='./cmd/tool' task test` or `PACKAGES='.' task test -- -run=TestName`: focused test run. `PACKAGES` is comma-separated when listing multiple packages.
- `task tidy`: run `go mod tidy` using the current Go version detected by Taskfile.
- `task clean`: removes `build/`, Task checksums, and generated `misc/version.go`.

## Checks And Hooks

- Pre-commit checks only gofmt; pre-push also runs `trivy --exit-code 1 fs --ignore-unfixed .`. Trivy is an external prerequisite if you rely on hooks.
- `task` tries to copy `scripts/git/pre-commit` and `scripts/git/pre-push` into `.git/hooks`, but this repo currently has no `scripts/git/` directory. If `task` fails there, run the narrower verification you need (`task test`, `go test`, `go tool staticcheck`) and report the hook-copy blocker.

## Testing Notes

- Root package tests use `testdata/*.yaml`; keep fixture updates alongside behavior changes in `Process`.
- `freeLocalPort` and network tests bind localhost TCP ports and keep a package-global reserved port map, so avoid assuming port-related tests are isolated across the whole process.
- `sanitize_test.go` uses a package-global `count` and explicitly notes it is not safe for multiple concurrent tests; do not add `t.Parallel()` around those tests without reworking shared state.
